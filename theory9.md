# Лабораторная 9 — теория для защиты

Работа с историей заказов, реализация полного цикла CRUD
(Create, Read, Update, Delete) через REST API, разработка модальных
окон и обработка серверных ответов.

## Что сделано в работе

1. Создана страница «Заказы» (`orders.html`) со ссылкой в шапке
   каждой страницы сайта (`index.html`, `lunch.html`, `order.html`,
   `orders.html`).
2. При загрузке страницы отправляется запрос
   `GET /labs/api/orders?api_key=...`, получающий все заказы текущего
   пользователя. Список сортируется по убыванию даты (`created_at`),
   новые заказы идут первыми.
3. В таблице отображаются: порядковый номер, дата оформления,
   состав заказа (названия блюд через запятую), суммарная стоимость,
   время доставки («Как можно скорее» либо точное время) и кнопки
   действий:
   - **Подробнее**: просмотр всей информации и состава в модальном окне.
   - **Редактирование**: изменение контактных данных и времени
     доставки (`PUT /labs/api/orders/{id}`).
   - **Удаление**: подтверждение удаления (`DELETE /labs/api/orders/{id}`).
4. Каждое модальное окно содержит кнопку-крестик вверху справа,
   закрывается по кнопке «Отмена» или клику на фон.
5. После успешного изменения или удаления выводится уведомление, а
   таблица заказов обновляется без перезагрузки всей страницы.

## Архитектура CRUD и REST API

- **C (Create)** — `POST /labs/api/orders` (реализовано в ЛР 8).
- **R (Read)** — `GET /labs/api/orders` (список всех заказов) и
  `GET /labs/api/orders/{id}` (конкретный заказ).
- **U (Update)** — `PUT /labs/api/orders/{id}` (обновление полей).
- **D (Delete)** — `DELETE /labs/api/orders/{id}` (удаление записи).
- Все запросы требуют указания персонального `api_key` в строке
  параметров URL (`?api_key=...`).
- Запросы `PUT` и `POST` передают обновляемые поля в теле запроса
  (`FormData` или `application/json`).

## Модальные окна (Modal Dialogs)

- Модальное окно блокирует взаимодействие с основным документом,
  пока пользователь не завершит действие или не закроет его.
- Реализуется через фиксированный оверлей (`position: fixed; inset: 0;
  background: rgba(0,0,0,0.5); z-index: 1000; display: flex;
  justify-content: center; align-items: center;`).
- Модальное окно внутри оверлея имеет `max-width`, прокрутку при
  переполнении (`max-height: 90vh; overflow-y: auto;`) и
  структурировано на `header`, `body`, `footer`.
- Для доступности фокус удерживается в модальном окне, а клик по
  самому оверлею (`event.target === overlay`) закрывает его.

## Вопросы и ответы для защиты

1. **В чём разница между методами PUT и POST?**
   `POST` создаёт новый ресурс на сервере (неидемпотентный).
   `PUT` обновляет или заменяет существующий ресурс по конкретному
   URI (идемпотентный).
2. **Как сортируются заказы?**
   По убыванию даты: `orders.sort((a, b) => new Date(b.created_at) -
   new Date(a.created_at))`.
3. **Что происходит при ошибке сервера (например, 502)?**
   Промис `fetch` завершается с ошибкой или `response.ok === false`,
   ошибка перехватывается в `.catch()`, модальное окно остаётся или
   показывает текст ошибки пользователю, не разрушая интерфейс.
4. **Зачем сопоставлять ID блюд из заказа с массивом `dishes`?**
   В заказе хранятся только числовые ключи (`soup_id`, `main_course_id`
   и т. д.). Чтобы показать человекочитаемые названия и цены,
   скрипт находит блюда по `dish.id` в кэше/API.
5. **Как устроено закрытие модального окна?**
   Скрывается оверлей (`overlay.hidden = true` или удаление из DOM),
   очищаются поля формы, восстанавливается доступность фона.
